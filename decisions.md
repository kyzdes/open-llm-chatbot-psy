# Лог решений — FreePsy

## 2026-02-12: Начальная архитектура

| # | Решение | Обоснование |
|---|---------|-------------|
| 1 | Python + aiogram 3.x | Богатая экосистема, нативная асинхронность, FSM из коробки |
| 2 | SQLite + aiosqlite (WAL mode) | Нет внешних зависимостей, достаточно для MVP |
| 3 | OpenRouter как LLM-провайдер | Единый API для множества бесплатных моделей |
| 4 | Keyword-based crisis detection (middleware) | Мгновенная реакция без задержки API |
| 5 | Скользящее окно ~100K токенов | Оставляет место для системного промпта и генерации |
| 6 | Typing keep-alive каждые 4с | Typing indicator Telegram живёт 5с, LLM думает дольше |
| 7 | Admin-only команды по user_id | Простой механизм управления для MVP |
| 8 | Strip `<think>` блоков regex'ом | Пользователю не нужен reasoning output |
| 9 | Token Bucket rate limiting (in-memory) | Достаточно для MVP, сброс при рестарте — приемлемо |
| 10 | therapy.router регистрируется последним | Catch-all не должен перехватывать другие хендлеры |

## 2026-02-13: UX-улучшения

| # | Решение | Обоснование |
|---|---------|-------------|
| 11 | HTML вместо Markdown для parse_mode | Надёжнее для Telegram, не ломается от LLM-разметки |
| 12 | Краткость как главное правило промпта | Пользователи читают с телефона, запрет списков → живой текст |
| 13 | Меню команд через set_my_commands() | Telegram показывает кнопку `/` → список команд |
| 14 | Динамический список моделей (inline-клавиатура) | Актуальный список, выбор кнопкой, валидация перед сохранением |

## 2026-03-01: Надёжность LLM

| # | Решение | Обоснование |
|---|---------|-------------|
| 20 | Retry на 5xx ошибки (не только 429) | Бесплатные модели часто возвращают 502/503 |
| 21 | Fallback на `openrouter/free` | Если основная модель отключена — пользователь всё равно получает ответ |
| 22 | `DEFAULT_MODEL` через env | Настройка дефолтной модели без изменения кода |
| 23 | Параллельная валидация моделей в `/modelchange` | Исключает мёртвые модели (400/404) до показа списка, ~4с вместо ~60с |
