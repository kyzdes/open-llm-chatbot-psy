# Архитектурное решение — FreePsy

## 1. Стек технологий

| Компонент | Технология | Обоснование |
|-----------|-----------|-------------|
| Язык | Python 3.11+ | Богатая экосистема для Telegram-ботов |
| Telegram-фреймворк | aiogram 3.x | Асинхронный, современный, FSM из коробки |
| HTTP-клиент | aiohttp | Асинхронные запросы к OpenRouter |
| База данных | SQLite + aiosqlite | Простота для MVP, нет внешних зависимостей |
| LLM API | OpenRouter | Единый API для множества бесплатных моделей |
| Конфигурация | python-dotenv | Безопасное хранение секретов |

## 2. Архитектура

```
Telegram ← aiogram → Handlers → Services → OpenRouter API
                         ↓            ↓
                    Middlewares    SQLite DB
                    (rate limit,   (users, messages,
                     crisis scan)   mood, settings,
                                    crisis_events)
                    Filters
                    (IsAdmin)
```

### Слои:
1. **Handlers** — обработка команд и сообщений
2. **Middlewares** — rate limiting, быстрый crisis scan
3. **Filters** — переиспользуемые фильтры (IsAdmin для админских команд)
4. **Services** — бизнес-логика (LLM, история, кризис, аналитика)
5. **Repositories** — доступ к данным (CRUD для каждой таблицы)
6. **DB Engine** — async context manager для соединений, WAL mode
7. **Utils** — форматирование (md→HTML), промпты, константы, оценка токенов
8. **Keyboards** — inline-клавиатуры (mood, reset, выбор модели)

## 3. Схема БД (SQLite)

### users
- `user_id` INTEGER PRIMARY KEY — Telegram user ID
- `username` TEXT
- `first_name` TEXT
- `language_code` TEXT
- `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP
- `is_blocked` INTEGER DEFAULT 0

### conversation_messages
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `user_id` INTEGER REFERENCES users(user_id)
- `role` TEXT — 'system' | 'user' | 'assistant'
- `content` TEXT
- `tokens_est` INTEGER
- `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP

### mood_entries
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `user_id` INTEGER REFERENCES users(user_id)
- `score` INTEGER CHECK(score BETWEEN 1 AND 10)
- `note` TEXT
- `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP

### bot_settings
- `key` TEXT PRIMARY KEY
- `value` TEXT

### crisis_events
- `id` INTEGER PRIMARY KEY AUTOINCREMENT
- `user_id` INTEGER REFERENCES users(user_id)
- `trigger` TEXT — 'keyword' | 'llm'
- `matched` TEXT — сработавшее слово/фраза
- `created_at` TIMESTAMP DEFAULT CURRENT_TIMESTAMP

## 4. Обработка сообщений (основной поток)

```
Пользователь → текст
  ↓
[Middleware: Rate Limit] — отклонить если превышен лимит
  ↓
[Middleware: Crisis Scan] — regex-проверка ключевых слов
  ↓
[Handler: therapy]
  1. Сохранить сообщение в БД
  2. Если crisis_detected → показать горячие линии
  3. build_messages() — скользящее окно ~100K токенов
  4. Запустить typing keep-alive (каждые 4с)
  5. LLM запрос → OpenRouter (retry 3x при 429/5xx/timeout, fallback на openrouter/free)
  6. Strip <think> блоков из ответа
  7. Сохранить ответ в БД
  8. Разбить на чанки (≤3500 символов)
  9. Конвертировать Markdown→HTML (md_to_html + sanitize_html)
  10. Отправить пользователю (parse_mode=HTML, fallback на plain text)
```

## 5. Crisis Detection

Мгновенная проверка через предкомпилированный regex из 51 ключевого слова (рус/англ). Выполняется в middleware до handler. Результат передаётся как `crisis_keyword` в data.

При срабатывании:
- Логирование в таблицу `crisis_events`
- Отправка контактов горячих линий
- Дополнительная system-инструкция для LLM (максимальная эмпатия)

## 6. Скользящее окно истории

- Бюджет: ~100K токенов
- Оценка токенов: `len(text.encode("utf-8")) // 4`
- Системный промпт всегда включён
- Старые сообщения обрезаются с начала

## 7. Rate Limiting

- Алгоритм: Token Bucket
- Параметры: 3 burst, 1 токен / 10 секунд
- In-memory (сбрасывается при перезапуске)
- Eviction бакетов старше 1 часа
- Применяется к каждому user_id отдельно

## 8. Динамический выбор модели

Запрос `GET /api/v1/models` к OpenRouter API.

- **Фильтрация**: бесплатные (`pricing.prompt == "0"`) + параллельная проверка доступности (исключаются модели с 400/404)
- **Кеш**: модульная переменная с `asyncio.Lock`, TTL 10 минут
- **UI**: inline-клавиатура, текущая модель помечена ✓, показываются все доступные модели
- **callback_data**: `model:{index}` — индекс в кешированном списке (защита от лимита 64 байта)
- **Валидация**: пробный запрос к модели перед сохранением
- **Fallback**: при отказе основной модели автоматический переход на `openrouter/free`

Модель по умолчанию: `stepfun/step-3.5-flash:free` (настраивается через env `DEFAULT_MODEL`).

## 9. Форматирование сообщений

Все сообщения бота используют `parse_mode="HTML"`.

- **Статические сообщения** (промпты, техники, команды): HTML-разметка в константах
- **LLM-ответы**: конвертация Markdown→HTML через `md_to_html()`:
  - Извлечение code blocks/inline code → `html.escape()` → форматирование → восстановление
  - ` ```code``` ` → `<pre>`, `` `code` `` → `<code>`
  - `**bold**` → `<b>`, `*italic*` → `<i>`, `## Header` → `<b>`
- **sanitize_html()**: stack-based закрытие незакрытых тегов (LIFO)
- **Fallback**: при `TelegramBadRequest` — отправка без parse_mode

## 10. Меню команд бота

При запуске вызывается `bot.set_my_commands()` — Telegram показывает пользовательские команды через кнопку `/` в поле ввода. Админские команды (`modelchange`, `setprompt`, `resetprompt`) не включены в меню.
